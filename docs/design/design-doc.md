# Дизайн-документ PWA «Корзинка»

Помощник покупок в гипермаркете АШАН Симферополь. Один пользователь, телефон
Redmi Note 12 4G, CSS viewport **393×873**, DPR **2.75**. Сценарий использования —
**в торговом зале, одной рукой, на ходу, часто на слабом Wi-Fi/LTE**.

Источники: живое исследование Яндекс.Лавки (`docs/design-research/lavka.md`,
высокое доверие — снято по реальному интерфейсу) и умозрительные заметки по
Самокату/Куперу (`samokat.md`, `kuper.md` — сайты были недоступны, авторы сами
пишут «вероятно», «типично»; из них взято только то, что совпадает со здравым
смыслом и с паттерном Лавки, отдельно помечено «низкое доверие»). Текущая
реализация — `web/index.html`, `web/style.css`, `web/app.js`.

---

## 0. Критика текущей версии (что чиним в первую очередь)

1. **«Дженерик слоп»** — карточка товара в списке визуально ничем не отличается
   от тысячи похожих delivery-приложений: серая рамка, скруглённый квадрат-фото,
   мелкий текст без иерархии. Нет ни одной детали, которая говорит «это про
   анализ состава и умные скидки», хотя это и есть суть продукта.
2. **Дублирующиеся бейджи скидки.** Сейчас в `itemHTML()` рядом стоят
   `<span class="badge disc">−59%</span>` и `dealBadge()` →
   `<span class="badge deal">выгода −67%</span>` — два бейджа об одном и том же,
   разными словами. Это тот самый «шум» — убираем, оставляем одну сущность
   (раздел 4.2).
3. **Разбитые фото.** `<img src=r.im>` без `onerror` — если ссылка не грузится,
   остаётся пустой alt-разрыв. Нужна закладка-заглушка на CSS/SVG, без сетевых
   запросов (раздел 4.4).
4. **Нижняя навигация не работала** — в `index.html` кнопки без `type="button"`
   внутри `<nav>`, которая не является `<form>`, так что по умолчанию проблем
   быть не должно, но реальная причина в проекте — не в скоупе этого документа;
   раздел 5 фиксирует ожидаемое поведение вкладок как контракт для реализации.

## 1. Дизайн-принципы

1. **Большой палец — самый ценный указатель.** Все интерактивные элементы,
   которые нажимаются в потоке покупки (переключение вкладки, +/− количества,
   «в список»), лежат в нижней трети экрана (0–873, зона thumb reach ~450–873px)
   и не мельче 44×44px. Ничего важного нельзя разместить в верхних 100px, куда
   тянуться неудобно при хвате одной рукой.
2. **Одна мысль — один взгляд.** На экране списка при беглом взгляде (~1 сек,
   тряска тележки, боковое зрение) должно читаться ровно три вещи: что это,
   сколько стоит, стоит ли брать. Всё остальное — по тапу в карточку. Не
   дублировать одну и ту же мысль двумя виджетами (см. критику про 2 бейджа).
3. **Работает при плохой сети и без неё.** Каждый экран имеет валидное
   состояние «пока грузится» (скелетон) и «не догрузилось» (заглушка, а не
   пустота/лом вёрстки). Данные каталога уже локальные (см. `data/*.json`),
   тяжёлое — только фото; никогда не блокировать интерфейс на фото.
4. **Числа — тяжелее слов.** Цена, %, оценка состава — это то, ради чего открыли
   приложение в магазине. Цифры получают вес 700 и табличные цифры
   (`font-variant-numeric: tabular-nums`), текст вокруг — обычный вес.
5. **Честность вместо тревоги.** Продукт живёт на недоверии к «фейковым»
   скидкам и мусорному составу — тон спокойный и фактический (без кричащих
   emoji-плашек), но статус всегда однозначен по цвету: зелёный = хорошо,
   янтарный = средне, терракотовый = плохо. Никакого чистого красного/зелёного
   светофора «как у всех» — см. палитру ниже, она уже такая, оставляем.

### 2.6 Тени

Только одна тень в системе — не плодить уровни:

```
--shadow-card: 0 1px 3px rgba(36,43,38,.06), 0 1px 2px rgba(36,43,38,.08);
```

Применяется к карточке товара и к плавающей нижней навигации (тень вверх:
`0 -1px 8px rgba(36,43,38,.06)`, плюс `border-top:1px solid var(--line)` как
сейчас). Модальная шторка — без тени, у неё есть затемнение фона (`rgba(0,0,0,.45)`,
уже есть в CSS).

## 3. Экраны

Все раскладки — под ширину 393px, зоны считаются от левого края с полями 12px.

### 3.1 Поиск / каталог (главный экран, вкладка «Поиск»)

```
┌─────────────────────────────────────┐ y=0
│  [ 🔍  Найти товар…            ]     │ 0–48   header, sticky
├─────────────────────────────────────┤
│ [Все ▾] [Сначала выгодные ▾] [☑ есть]│ 48–88  фильтры, sticky
├─────────────────────────────────────┤
│  ░░ Молочное ░░ Овощи ░░ Мясо ░░ …  →│ 88–128 чипы категорий (скролл), опционально
├─────────────────────────────────────┤
│ ┌───┐ Название товара            │  │
│ │фот│ Бренд · 500 г               │  │ 128…  список карточек, 1 колонка
│ └───┘ [состав 78]      129 ₽ [+]  │  │        высота карточки ~84px
├─────────────────────────────────────┤
│              …                      │
├─────────────────────────────────────┤
│  🔍Поиск  🔥Скидки  🧺Список³ ⚙️Моё │ 809–873 bottom nav, fixed, 64px+safe-area
└─────────────────────────────────────┘
```

Список — **1 колонка**, а не 2×N как у Лавки/Самоката: у нас на карточке
больше значимых чисел (цена, цена/кг, оценка состава), в 2 колонках по 185px
это не влезет читаемо. Одноколоночный плотный список — сознательное отличие
от конкурентов, оправданное количеством данных на товар (см. п.4.1).

Порядок важности сверху вниз/внутри карточки: **название → цена → оценка
состава/выгода → второстепенное (бренд, рейтинг)**. Поиск — первое, на что
падает взгляд и палец при входе в приложение (сценарий «стоя перед полкой»).

Категории вынесены в чипы горизонтального скролла (заимствовано у Лавки,
доверие высокое) — сейчас это `<select>`, что на 393px и при работе одной
рукой неудобно (нужно два тапа: открыть select, выбрать). Чипы — один тап.

### 3.2 Скидки (вкладка «Скидки»)

Та же структура списка, что в 3.1, но:
- нет фильтра категорий по умолчанию (можно раскрыть по чипу «Ещё фильтры»),
- сортировка по умолчанию — «Сначала выгодные» (уже так в `app.js`),
- вверху списка — короткая строка-легенда, не баннер:
  `Показаны товары со скидкой ≥5% от обычной цены · 12 фейковых скрыто`
  (12px, `--muted`, без фона) — это честный аналог «баннера доставки» у
  конкурентов, но без рекламного шума.
- карточки с «фейковой» скидкой (`rel >= -1`, см. `dealBadge()`) в эту вкладку
  **не попадают вовсе** — вкладка «Скидки» показывает только настоящую выгоду,
  это и есть продуктовая ценность фичи, нет смысла показывать разоблачённые
  скидки в разделе, который называется «Скидки».

## 4. Компоненты

### 4.1 Карточка товара в списке — что показываем, что убираем

**Оставить (по убыванию значимости):**
1. Название (1 строка, ellipsis — не 2-3 как в детальной; в списке короче)
2. Цена сейчас, крупно, 16px/700
3. Один бейдж выгоды/скидки (см. 4.2) — только если есть скидка
4. Шкала/чип оценки состава (см. 4.3) — компактный вариант
5. Цена за кг/л, если применимо (12px, ink2, справа под ценой)
6. Кнопка +/− количества справа (см. 4.5)

**Убрать из списка (перенести в детальную карточку или не показывать вовсе):**
- Рейтинг ★ и число отзывов — на списке это шум, конкуренты (Лавка) держат
  его мелким серым 11px не просто так, это низкоприоритетная информация;
  здесь убираем совсем, не помогает решению «брать/не брать» в моменте.
- Старая зачёркнутая цена рядом с новой в списке — дублирует бейдж выгоды.
  Оставляем только в детальной карточке, где есть место и она даёт контекст.
- Флаги состава (сахар первым, пальмовое масло и т.д.) — только в детальной
  карточке, в списке достаточно агрегированного числа состава.

Итого строка карточки в списке становится короче текущей на ~30% визуального
шума при том же наборе решающих данных.

### 4.2 Бейдж выгоды — ОДНА сущность вместо двух

Сейчас: `−59%` (badge disc) + `выгода −67%` (badge deal) — два бейджа про одну
скидку разными словами. Заменяем на единый бейдж с логикой:

| Ситуация (по данным `r.d`, `r.rel`) | Бейдж | Цвет |
|---|---|---|
| Скидка есть, `rel <= -5` (реальная выгода) | `−59% · выгодно` | `--accent` заливка |
| Скидка есть, `rel >= -1` (цена как обычно, накрутка-разгон) | `цена как обычно` | outline `--warn`, без % |
| Скидка есть, `rel` между −1 и −5 (небольшая реальная скидка) | `−12%` | `--card-sunken` фон, `--ink2` текст, приглушённо |
| Скидки нет | ничего | — |

Один `<span class="badge">` на карточку, максимум. Текст внутри — «выгода»
или «%» никогда не дублируются в одной строке.

### 4.3 Шкала оценки состава

Компактная (список): горизонтальная полоска 40×6px + число.
`▓▓▓▓▓▓▓░░░ 78` — заливка пропорциональна 0–100, цвет заливки:
`--accent` (67–100), `--warn` (34–66), `--bad` (0–33).

Полная (карточка товара): полоска на всю ширину контента (~24px высоты со
скруглением 6px), число крупно (20px/700) слева от неё, под полоской —
`лучше 82% товаров в категории` (13px, ink2). Е-добавки — отдельным рядом
чипов под шкалой, а не встроены в неё (сейчас уже так, оставляем этот паттерн
из `.e-list`/`.e`, он рабочий).

### 4.4 Заглушка фото

Проблема сейчас: `<img src="">` без фолбэка → битая иконка браузера.
Решение — CSS/инлайн-SVG заглушка, без сетевых запросов, отрисовывается сразу:
- Квадрат `--card-sunken` фон, скругление 10px (список) / 10px (детальная).
- По центру — простая монохромная SVG-иконка пакета/корзины, `--muted`,
  30% от размера контейнера.
- `<img>` получает `onerror`, который скрывает `<img>` и показывает соседний
  `.img-fallback` (уже готовый DOM-узел, не создаётся по событию — избегаем
  layout shift).
- Заглушка визуально узнаваема как «нет фото», а не как «ошибка загрузки» —
  без красных крестиков и текста «error».

### 4.5 Кнопка +/− количества в списке

- Пока товара нет в списке покупок: одна кнопка `+` (32×32px, круг,
  `--accent` outline, знак `+` по центру), при тапе — не переходит в карточку,
  добавляет 1 шт. и мгновенно превращается в счётчик.
- В списке: `[ − ]  2  [ + ]`, кнопки 28×28px, число между ними 14px/700
  tabular-nums. Тап `+`/`-` не должен открывать детальную карточку —
  `event.stopPropagation()` на уровне обработчика (уже частично есть паттерн
  в `renderCart`, переносим на список товаров).
- Минимальная зона нажатия с учётом визуального размера 28px — добить
  невидимым паддингом до 40×40px (팁 из «thumb-friendly», принцип 1).

### 4.6 Скелетоны загрузки

- Список: 4–5 карточек-плейсхолдеров той же геометрии (84px), с
  `--card-sunken` прямоугольниками вместо текста/фото, лёгкая
  shimmer-анимация (см. 5).
- Карточка товара (шторка): плейсхолдер фото + 3 строки-полоски вместо
  текста, шторка открывается сразу (не ждёт данных), скелетон живёт внутри.
- Никогда не показывать пустой белый экран дольше ~100мс.

### 4.7 Пустые состояния

| Экран | Иконка | Заголовок | Подпись | Действие |
|---|---|---|---|---|
| Поиск, нет результатов | лупа (48px, `--muted`) | «Ничего не нашлось» | «Проверьте написание или уберите фильтры» | кнопка «Сбросить фильтры» (ghost) |
| Скидки, пусто | — | «Сейчас нет проверенных скидок» | «Список обновляется вместе с ценами каждый день» | — |
| Список покупок, пусто | корзина (48px) | «Список пуст» | «Добавляйте товары кнопкой + в поиске» | кнопка «К поиску» → переключает вкладку |
| Любимое, пусто | сердце-контур | «Пока нет избранного» | «Отмечайте товары ♡ в карточке» | — |

Единый визуальный язык пустых состояний: иконка `--muted` 48px, заголовок
15px/600 `--ink`, подпись 13px `--ink2`, вертикальный паддинг 40px сверху.

## 5. Микровзаимодействия

- **Переключение вкладок**: мгновенно, без анимации перехода (contentchange,
  не page-slide) — вкладки внутри одного PWA-контейнера, slide-анимация между
  ними (как у Лавки, 300мс) добавляет задержку без пользы на слабом
  устройстве; экономим на анимациях, тратим бюджет на отклик.
- **Открытие карточки товара**: шторка снизу, `transform: translateY` 220мс
  `ease-out`, затемнение фона одновременно `opacity` 220мс.
- **Тап по карточке/кнопке**: `background` через `:active` состояние, 100мс,
  без задержки на распознавание тапа (`touch-action: manipulation` в CSS,
  чтобы убрать 300мс delay браузера).
- **Добавление в список** (тап `+`): счётчик появляется без анимации
  масштабирования карточки — уже есть числовой feedback (счётчик), доп.
  scale-анимация из исследования Лавки — decorative, пропускаем ради простоты
  реализации и производительности на бюджетном устройстве.
- **Скелетон → контент**: shimmer-градиент, движение слева направо, 1.2с
  цикл, `--card-sunken` → чуть светлее → `--card-sunken`; останавливается и
  заменяется реальным контентом без fade (мгновенно, чтобы не тормозить).
- **Свайп влево на строке списка покупок**: открывает кнопку «Удалить»
  (`--danger` фон), порог срабатывания 80px, с haptics не будет (нет доступа/
  не нужно, PWA), визуальная пружинка на отпускании — `ease-out` 150мс.
- **Pull-to-refresh** — не делать: список из локальных данных (`data/*.json`),
  обновление каталога — не по требованию пользователя посреди покупок,
  а по факту нового среза при следующем заходе. Лишний жест без применения.

Haptics действительно нет (задание явно это оговаривает) — все состояния
подтверждаются только визуально.

## 6. Чего не делать (антипаттерны)

Из исследований конкурентов и общих «ИИ-дефолтов»:

1. **Не дублировать одну метрику двумя виджетами** — главная находка критики
   текущей версии (`−59%` + `выгода −67%`). Правило на будущее: если два
   элемента интерфейса отвечают на один и тот же вопрос пользователя — один
   из них лишний.
2. **Не заводить промо-баннеры/карусели** (Лавка, п.3 её структуры — яркий
   баннер доставки + карусель промо). У нас нет доставки и нет маркетинговых
   акций магазина, которые мы контролируем — баннер был бы пустой имитацией
   чужого паттерна. «Скидки» и так отдельная вкладка.
3. **Не городить 5 вкладок нижней навигации ради «стандартности».**
   Рекомендация из `lavka.md` (низкое доверие в части «Профиль») скопирована
   под сервис с доставкой и аккаунтом — у нас их нет. 4 вкладки, которые уже
   есть в `index.html` (Поиск/Скидки/Список/Моё), — правильное число, не
   добавлять пятую «для симметрии».
4. **Не красить весь интерфейс в «типовой» оранжево-жёлтый delivery-стиль.**
   Оранжевый/жёлтый у Лавки и Самоката — их брендинг про скорость доставки;
   у нас про доверие к анализу данных. Держим зелёный/нейтральный, это уже
   заложено в токенах — не менять «для узнаваемости».
5. **Не показывать рейтинг ★ и число отзывов в списке товаров** (см. 4.1) —
   типовой элемент карточки в доставке, но не помогает нашей главной задаче
   (оценка состава важнее субъективных отзывов о вкусе).
6. **Не использовать 2-колоночную сетку «потому что так у всех».** Обоснование
   в 3.1 — у нас на карточке больше решающих цифр, чем в типичном
   delivery-приложении, широкая одноколоночная строка читается быстрее при
   беглом взгляде на ходу.
7. **Не блокировать интерфейс на загрузке фото** — фото всегда `loading="lazy"`,
   разрыв фото никогда не должен трогать layout (заглушка фиксированного
   размера, никакого layout shift при переходе placeholder → реальное фото).
8. **Не плодить уровни теней/скруглений «для глубины».** Один уровень тени
   (2.6), три уровня скругления по смыслу (карточка/кнопка/чип) — этого
   достаточно, лишние вариации — типичный ИИ-дефолт «добавить полутени
   везде», создаёт визуальный шум без функции.
9. **Не делать confirm()-алерты браузера для подтверждений** (сейчас в
   `app.js` используется нативный `confirm()` для очистки списка и скрытия
   бренда) — на телефоне это грубо ломает визуальный стиль; в целевой
   реализации заменить на in-app подтверждение (небольшой inline-тост или
   вторичная кнопка «точно?»), но это уже вопрос реализации, не разметки.
10. **Не превращать оценку состава в «страшилку».** Даже для низкой оценки —
    терракотовый (`--bad`/`--danger`), не чистый красный, без иконок черепа/
    восклицательных знаков в кружках. Тон фактический, не алармистский
    (принцип 5).

## Файл и ключевые решения

Документ сохранён: `E:\claude work\auchan\docs\design\design-doc.md`

**5 ключевых решений:**
1. Один бейдж выгоды вместо двух, с тремя состояниями (выгодно / цена как
   обычно / небольшая скидка) — устраняет главную претензию к текущей версии.
2. Список товаров — одна колонка на всю ширину, а не 2×N как у конкурентов:
   у нас на карточке больше решающих цифр (цена, цена/кг, оценка состава),
   двум колонкам они не помещаются читаемо.
3. Из карточки списка убраны рейтинг/отзывы и вторая (старая) цена — остаются
   только название, цена, один бейдж выгоды, компактная шкала состава,
   цена/кг и кнопка количества.
4. Заглушка фото — заранее отрисованный SVG-плейсхолдер с `--card-sunken`
   фоном и `onerror`-переключением на готовый DOM-узел, без layout shift.
5. Палитра остаётся зелёно-нейтральной (не оранжево-жёлтой «под доставку») и
   не алармистской для плохих оценок состава — фактический тон вместо тревоги,
   как формулирует принцип 5.
