# Хендофф: живые цены и редизайн PWA под прототип

Брифинг для следующей сессии. Здесь всё, что нужно знать, чтобы начать
работу без раскопок: где проект сейчас, какие решения уже приняты и почему,
что именно предстоит сделать.

расходится с утверждённым эталоном дизайна. Данные грузит статикой.

## Задача 1. Редизайн под прототип

Эталон — [design_handoff_shopping_list/](../design_handoff_shopping_list/),
хендофф из Claude Design. Цвета, типографика, отступы, радиусы и тайминги
там **финальные, воспроизводить точно**. При любом расхождении с текущим
`web/` побеждает прототип.

| файл | что внутри |
|---|---|
| `DESIGN_SYSTEM.md` | токены, типографика, сетка, радиусы, тени, движение, тон текста |
| `README.md` | пять экранов и три шторки, механики и тексты состояний |
| `Прототип.dc.html` | живой макет, `support.js` — его логика |

Известные расхождения:

| | сейчас в web/ | прототип |
|---|---|---|
| оценка состава | число 0–100, три цвета | буква A–E, пятицветная шкала |
| гарнитура | Inter / системная | Golos Text 400–800 |
| вкладка | «Любимое» | «Избранное» |
| исключения | только скрывать | скрывать **или** помечать |
| онбординг | нет | есть (выбор бюджета, чипы «чего не показывать») |
| движение | почти нет | три скорости, каскады, пружины |
| сортировка | чипы-комбинатор | сегменты с едущей плашкой + «ещё» |
| шапка ленты | статичная | сворачивается при скролле |
| карточки | обычная сетка | subgrid, выравнивание по общей сетке |

Детали каждого экрана — в `README.md` прототипа, пересказывать здесь нет
смысла, там всё разобрано по пикселям.

## Задача 2. Живые цены вместо статики

**Зачем.** В магазине нужна цена и наличие «на сейчас», а не вчерашние.
Сейчас всё лежит статикой и протухает за сутки.

**Что мешает.** Браузер не даст JS прочитать ответ auchan.ru с чужого
домена: API не отдаёт заголовок `Access-Control-Allow-Origin` — проверено
2026-08-15 на GET и на preflight OPTIONS, заголовка нет вовсе. Нужен
посредник: серверный код, который сам сходит к API и вернёт ответ со своим
разрешающим заголовком. GitHub Pages раздаёт только файлы, выполнять код
там негде.

**Целевое разделение данных:**

| откуда | что |
|---|---|
| живьём через прокси | цена, старая цена, скидка с датами, наличие — только для видимых карточек и того, что в списке покупок |
| статикой из репозитория | оценка состава и буква A–E, типичная цена по истории (основа «умных скидок»), график цены, скелет каталога для поиска |

Батч-эндпоинт под это уже есть: `POST /v3/catalog/get-products/` — запрос
по списку артикулов (см. [auchan-api.md](auchan-api.md), §8). Листинг
категории тоже отдаёт цену и остаток сразу, без карточек — именно на этом
построен `snapshot_prices.py`.

Побочный выигрыш: из `index.json` уходят все цены, и он худеет с нынешних
6,6 МБ.

**Где разместить прокси** (~30 строк кода):

| где | цена | подвох |
|---|---|---|
| Yandex Cloud Functions + API Gateway | бесплатно (1 млн вызовов/мес) | при регистрации просят карту; в пределах бесплатного тарифа не спишут |
| Cloudflare Workers | бесплатно (100 тыс./день) | американский, регистрация из Крыма под вопросом |
| VPS | ~200 ₽/мес | платно, зато сайт, прокси и вход по паролю на одной машине |

Рекомендация — **Yandex Cloud Functions**: бесплатно и без регионального
риска. Требует аккаунта пользователя, за него это сделать нельзя.

## Принятые решения

- **Хостинг — GitHub Pages**, бесплатно и с HTTPS (нужен для service worker).
- **Пароля на сайте не будет.** На Pages его поставить нельзя в принципе
  (это фича Enterprise Cloud), а защищать нечего: список покупок, бюджет,
  любимое и чёрные списки лежат в `localStorage` телефона и на сервер не
  уходят. Достаточно **неприметного адреса** — переименовать репозиторий из
  `test` во что-то случайное и добавить `<meta name="robots" content="noindex">`.
  После переименования обновить remote: `git remote set-url origin <новый URL>`.
- Только светлая тема, тёмной нет по решению пользователя.
- Полный каталог в облаке не гоняется — только пищевой срез.

## Порядок работы

1. Поднять текущую PWA на GitHub Pages — быстрый шаг, приложение станет
   доступно с телефона, дальше правки видно сразу на живом.
2. Редизайн под прототип, по экранам. Процесс с субагентами описан в
   [pwa-korzinka.md](pwa-korzinka.md) и себя оправдал: реализация на Opus с
   обязательным самопрогоном кликами и скриншотами, независимая приёмка на
   Sonnet, фиксы и коммит после каждого цикла.
3. Прокси живых цен и перевод карточек на живые данные.

Порядок 2 и 3 можно менять местами, они почти не пересекаются: редизайн
трогает вёрстку и `style.css`, живые цены — слой данных в `app.js`.

## Что не забыть

- **Поднимать версию кэшей в `sw.js` при каждой правке `web/`** (сейчас v9),
  иначе у пользователя залипнет старая оболочка.
- Шардинг деталей — сумма кодов символов `code % 32`, формула продублирована
  в `build_site_data.py` и `app.js`, менять синхронно.
- GitHub гасит расписание workflow после 60 дней без активности в
  репозитории, и коммиты бота активностью не считаются. Сторож это поймает.
- История цен на 2026-08-15 — 4 дня (11, 12, 14, 15 августа). «Умные скидки»
  станут честными после недели-двух накопления.
